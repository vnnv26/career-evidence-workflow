# Reusable Resume Workspace

Use this reference when a user uploads an evidence bank or resume package, imports a resume for the first time, or wants a portable workspace.

## Independent layers

Keep these layers separate when they exist:

1. `evidence-bank.md` — the user's richest factual source, including evidence not selected for the current resume;
2. `candidate-profile.md` — a compact, sourced working summary used for personalized analysis;
3. `workflow-profile.md` — optional stable task, market, language, format, and update preferences;
4. `base-resume.md` — current general-purpose resume content and section order;
5. `layout-profile.md` — visual and structural preferences needed to recreate the source design;
6. `reuse-library.md` — optional accepted wording variants linked back to evidence;
7. an optional editable master or source document in the user's chosen format.

Localized filenames are equally valid. Preserve the names in an uploaded package unless changing them has a clear benefit and the user agrees.

## Using an uploaded evidence bank

Read the user's uploaded bank before requesting another resume. Use the base resume for current selection and wording, the evidence bank for deeper facts, and the layout profile only when producing an artifact.

Request a new source resume only when the user says it changed, asks for a different design, or required content or layout cannot be reconstructed from the supplied package.

## Building a workspace

When the user has no reusable package:

1. extract visible content and relationship types from the supplied resume or materials;
2. record factual evidence separately from resume wording;
3. record layout only if the user wants future artifact recreation;
4. show material extracted facts and uncertainties for correction;
5. save files only in a user-authorized location.

## Updating

- New facts and corrected data update the evidence bank.
- Regenerate or patch the candidate profile when source evidence changes materially; do not let it override the underlying bank.
- Update the workflow profile only when the user changes a stable preference.
- A tailored application remains a target-specific output.
- Update the base resume only when the user adopts a change as the new general default.
- Preserve a `last confirmed` date when staleness matters.
- Never merge this workspace with another person's bank or include it in the distributed skill.

## Portable package

Offer a compact portable package only when useful. A typical package is:

```text
evidence-bank.md
candidate-profile.md
workflow-profile.md       # optional
base-resume.md
layout-profile.md
reuse-library.md        # optional
```

The user can upload this package in a future conversation without repeatedly supplying the original resume.
