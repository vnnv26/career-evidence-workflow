# Intake and User Preferences

Use this reference on a new user's first run or when the task context has materially changed.

## Evidence-bank intake

Offer two valid starting paths:

1. **Upload an existing evidence bank.** Accept Markdown, documents, exported shared pages, structured notes, or another readable format. Treat it as the user's source, not as a template to publish or merge with another person's records.
2. **Build a new evidence bank.** Use the user's own resume, portfolio, profiles, work samples, notes, transcripts, shared documents, and narrative answers.

If a bank is uploaded:

- read its structure and latest-confirmed dates before proposing changes;
- preserve usable terminology and identifiers;
- identify stale facts, contradictions, missing ownership, and unsupported resume wording;
- ask whether the uploaded file is the complete current bank or an excerpt only when the distinction affects the task;
- do not require the user's original resume again unless the bank lacks necessary current content or layout information.

Before materially rewriting an uploaded bank, provide a compact import health check covering:

- whether the upload appears complete or partial;
- latest confirmation dates and likely stale records;
- conflicting dates, titles, metrics, or relationship types;
- claims missing personal-versus-team ownership;
- results missing metric definitions, baselines, or time ranges;
- resume wording that lacks underlying evidence;
- high-value experiences that are underdeveloped;
- the smallest set of questions needed before the target task can proceed.

Do not treat a health check as permission to reorganize or rewrite the entire bank.

Never look for, import, or infer an evidence bank belonging to another user. A skill package must contain no real person's evidence bank.

## Minimum preferences

Infer from the request when clear; otherwise ask only what materially changes the work:

- target market and output language;
- current task: build/update evidence, analyze a JD, tailor a resume, or combine them;
- desired depth: Quick, Standard, or Deep;
- single-JD application versus reusable general resume;
- requested output format and application channel;
- page, layout, section, tone, privacy, and photograph preferences;
- whether the user wants automatic evidence-bank updates, confirm-before-write updates, or manual-only updates;
- whether a shared live source should be revisited on later runs.

When the user wants persistent preferences, store them in `workflow-profile.md` using the neutral template in `../assets/workflow-profile-template.md`. This profile contains workflow settings and constraints, not career evidence.

Do not assume a country, language, platform, paper size, one-page preference, file format, or fixed resume module order.

## Source access

When the user supplies a live shared document, use it only if the environment can access it. State access limitations and use the newest user-provided snapshot without claiming synchronization.

Do not publish, share, upload, or move the user's source material unless explicitly requested.

External research must not include the user's name, contact details, resume text, private evidence, or confidential project material unless the user explicitly authorizes a specific disclosure. Role research normally requires only the JD, company, role, product, and public business context.
